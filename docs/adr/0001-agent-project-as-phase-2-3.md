# ADR-0001：Agent API 服务合并为阶段 2+3 主线项目

- **日期**：2026-08-09
- **状态**：已接受

## 背景

原计划阶段 2（link-health-api 引导式热身）与阶段 3（独立 Capstone）分开推进，
周期分别为第 3-4 周和第 5-8 周。同时用户需完成一个实习导向的 agent 开发项目，
实习窗口为大二下（明年春天）。

## 决策

**跳过 link-health-api，将 Agent API 服务作为阶段 2+3 的合并主线项目。**

理由：
- link-health-api 与 Agent API 服务的技能点高度重叠（HTTP API、异步任务、
  并发调度、存储、测试），本质是同一项目的两种形态。
- 实习窗口在即，两条线串行会导致 agent 项目被过度推迟。
- Agent 项目用 Go 写后端，实现"一鱼两吃"：一个项目同时证明 Go 后端能力
  与 LLM/Agent 视野。

## 风险

1. **跨度大**：用户刚在 1.5 入门 httptest，直接上完整项目可能再次"复制粘贴不会写"。
2. **范围蔓延**：agent 项目方向容易无限膨胀，必须定义 MVP 边界。

## 缓解

- 将项目拆成里程碑，每个里程碑一个可验收的垂直切片。
- 教学方式延续"先讲工具 → 用户想思路 → 用户写代码"。
- 先定义 MVP 范围（见 ADR-0002），再动手。
